# 项目路线图

## 当前目标

先建立可靠、可追溯的中山大学哲学考研真题库，再实现最简单的关键词检索。

## 第一阶段：整理真题

- [x] 创建 `data`、`src` 和 `docs` 目录
- [x] 确定真题 JSON 数据格式
- [x] 检查中哲、西哲 PDF 来源
- [x] 录入并校对 2023-2025 年真题
- [x] 录入并校对 2015-2022 年真题
- [x] 录入并校对 2008-2014 年真题
- [x] 录入并校对现有的 2003-2006 年真题
- [x] 录入并校对 2026 年真题
- [ ] 寻找目前缺失的 2007 年真题
- [x] 补充此前缺失的 2003 年西哲真题
- [x] 补录 2004、2005 年西哲原著分析题的材料全文

整理时遵循以下原则：

1. 原始正式试卷优先于回忆版和汇编版。
2. 保留年份、科目、题号和来源页码；题型按原卷出现顺序归入三类。
3. 材料题的材料原文存入 `passage` 字段。
4. 双来源核对后使用 `cross_checked`；只有一个来源时使用
   `single_source`。
5. 无法确认的文字不自行补写，应在后续校对时单独标记。

## 第四阶段：发布网页

### 已确定的发布方案

- [x] 采用 GitHub Pages 对公开网页进行静态托管
- [x] 保持 `HTML + CSS + JavaScript + JSON` 的纯静态网页结构
- [x] 由浏览器读取 `data/questions.json` 并完成关键词、年份和科目筛选
- [x] 在线版本不运行 Python 后端，不购买或维护独立服务器
- [x] `src/search.py` 和 `src/search_web.py` 继续用于本地检索、调试和辅助维护，
  不作为 GitHub Pages 在线网站的运行依赖

### 为什么选择 GitHub Pages？

项目当前应把有限资源优先投入真题整理与检索体验，而不是提前建设和维护服务器。
现有功能完全可以在浏览器中完成，若专门部署 Python 后端，服务器大部分时间可能
只是在云端思考笛卡尔的存在和黑格尔的存在的同异关系。因此，本项目采用免费、
稳定且维护成本较低的 GitHub Pages：先让真题顺利上线，再让服务器等待一个真正
需要它的理由。未来加入 AI 问答、用户账户或在线编辑等功能时，再重新评估后端和
服务器方案。
