# 检索库选型评估

评估日期：2026-07-28

## 结论

当前继续使用项目内已有的零依赖检索实现，不引入 MiniSearch 或 ItemsJS。

这不是因为第三方库速度不够，而是因为：

1. 当前只有 431 道题，现有扫描检索的平均耗时约为 0.43 毫秒，尚无性能瓶颈。
2. 当前实现已经明确支持中文子串、空格 AND、`OR`、引号短语、前置减号排除、
   标签别名、结构化筛选和自定义相关度排序。
3. MiniSearch 的默认分词不能完整保留现有中文子串语义；若引入，必须先设计并
   验证中文 tokenizer。
4. ItemsJS 的优势是分面筛选和聚合，但项目已经具备所需的标签计数、AND/OR
   筛选、排序和分页基础；它的原生全文检索在本次中文样本中没有返回结果。
5. 引入任一库都会增加浏览器下载、索引初始化和维护成本，却暂时不能解决一个
   已经确认的用户问题。

## 候选定位

### 当前实现

- 直接扫描浏览器中加载的题目数组，无索引初始化阶段。
- 中文按规范名称和别名进行子串匹配。
- 查询表达式和结构化筛选由项目自己控制，行为已有测试覆盖。
- 缺少拼写容错、自动补全以及适合大数据集的倒排索引。

### MiniSearch 7.2.0

[MiniSearch 官方仓库](https://github.com/lucaong/minisearch)将其定位为浏览器和
Node.js 可用的内存全文检索库，支持字段加权、前缀匹配、模糊匹配、自动建议和
相关度排序，且没有运行时依赖。

它适合将来增加拼写容错或自动补全。不过，官方说明中的默认 tokenizer 按 Unicode
空白和标点切词。中文题干通常没有词间空格，因此默认索引不能等价替代当前的中文
子串检索。自定义 tokenizer 虽然可行，但必须另行决定中文切词或 n-gram 规则，并
通过现有查询语义的回归测试。

### ItemsJS 2.1.24

[ItemsJS 官方仓库](https://github.com/itemsapi/itemsjs)将其定位为 JSON 数据的
分面检索引擎，提供全文检索、相关度、分面计数与筛选、排序和分页，并支持分面内
AND/OR。官方也提供把全文检索交给 MiniSearch、再把命中 ID 交回 ItemsJS 的集成
方式。

它的分面能力与当前标签筛选最接近，但项目的数据量和分面数量都很小，现有实现
已经覆盖这些需求。实测中，ItemsJS 的精确“哲学家=康德”分面返回 26 道题，与
数据标签一致；其原生全文检索对本次中文查询均未命中，不能直接替换当前检索。

## 实测方法

环境：

- Windows，Node.js 24.18.0
- `data/questions.json`，共 431 道题
- MiniSearch 7.2.0
- ItemsJS 2.1.24
- 两个第三方包仅安装在系统临时目录，没有加入项目依赖

三种实现都检索题干、材料以及人物、流派、时期、主题、著作标签。性能数据不含
读取和解析同一个 JSON 文件的时间。

- 构建耗时取 21 次运行的中位数。
- 查询耗时经过 200 次预热，再取多次“康德”查询的平均值。
- 当前实现按实际采用的逐题中文子串匹配方式测试。
- 第三方库使用官方默认全文检索配置，不额外引入未经确认的中文分词策略。

## 结果

### 初始化和查询耗时

| 实现 | 初始化中位数 | 单次查询平均值 | 浏览器构建文件 |
| --- | ---: | ---: | ---: |
| 当前实现 | 0 ms（无索引） | 0.430 ms | 无新增依赖 |
| MiniSearch | 13.284 ms | 0.018 ms | 约 86 KB（未压缩 UMD） |
| ItemsJS | 1.630 ms | 0.135 ms | 约 57 KB（未压缩 UMD） |

第三方库的查询速度确实更快，但当前实现扫描全部 431 道题仍不足 1 毫秒。页面实际
体验更可能受 JSON 下载、DOM 渲染和结果数量影响，而不是这段匹配计算。

### 中文命中数量

| 查询 | 当前实现 | MiniSearch 默认配置 | ItemsJS 原生全文 |
| --- | ---: | ---: | ---: |
| 康德 | 27 | 26 | 0 |
| 黑格尔 | 17 | 17 | 0 |
| 哥白尼转向 | 1 | 1 | 0 |
| 知行合一 | 2 | 2 | 0 |
| 理 | 107 | 1 | 0 |
| 认识论 | 3 | 1 | 0 |
| 实践理性 | 3 | 0 | 0 |

MiniSearch 漏掉的“康德”结果是题干
“费希特是如何批评改造康德的先验哲学的？”。该题没有“康德”人物标签，默认
tokenizer 又把连续中文题干视为较长 token，因此没有获得当前实现的题干子串命中。
“理”“认识论”“实践理性”的差异也说明这不是偶发现象。

## 决策边界

满足以下任一条件时，重新评估 MiniSearch：

- 题目和关联材料增长到至少 5,000 条，或目标设备上的检索计算持续超过 50 ms。
- 拼写容错、前缀建议或自动补全成为明确需求。
- 已经确定中文 tokenizer 方案，并能通过当前 AND、OR、短语、排除和别名语义的
  回归测试。

满足以下任一条件时，重新评估 ItemsJS：

- 标签分面数量和组合显著增加，现有计数或筛选出现可测量的性能问题。
- 需要通用的动态分面、分页快照或由外部全文检索器返回 ID 后再做分面聚合。

在这些条件出现前，继续完善现有实现的测试和交互，比更换检索库更直接。
